# shell-update-site

The Keycard Shell update site, as a static GitHub Pages build. The markup, styles, scripts and look
are those of [keycard-shell-webapp](https://github.com/keycard-tech/keycard-shell-webapp); what is
gone is the Python backend. The firmware and the token database it used to serve from `MEDIA_ROOT`
are mirrored at build time from their GitHub releases:

- firmware: [keycard-tech/keycard-shell/releases/latest](https://github.com/keycard-tech/keycard-shell/releases/latest)
- database: [keycard-tech/keycard-eth-db/releases/latest](https://github.com/keycard-tech/keycard-eth-db/releases/latest)

Pages: the Owner's hub (`/`), Update, Air-gapped update, Database version history, Firmware release
notes. Device verification is not ported yet; its links go to the live site.

## Build and run

Node 22 or newer. Everything below is plain npm, no backend, no database.

```console
npm ci
npm run build          # render pages, sync artifacts, parcel, copy media into dist/
npm run typecheck      # tsc --noEmit over src/js
npm start              # dev server on the rendered pages, re-syncing first
npm run sync -- --dry-run   # ask what upstream has that the last build does not
```

Preview any build with any static server rooted at `dist/`, e.g.
`python3 -m http.server --directory dist`.

The update flow itself needs a Chromium browser and a secure context: `https://` or `http://localhost`
(a LAN address gives no `navigator.hid`). The device picker is the browser's own, and cancelling it is
a rejected connection like any other: the page logs `Connection error` and stays on the connect screen,
as keycard-shell-webapp does. That one line covers every failure, so check in that order: a browser
without WebHID, an address that is not a secure context, a dismissed picker, and on Linux the udev
rules that let the browser open the Shell at all — without them the device is picked and then cannot be
opened, which looks identical to a cancel.

Publishing is a GitHub Actions workflow: `.github/workflows/sync-and-deploy.yml` builds and deploys
`dist/` to GitHub Pages on push, on a schedule, and on dispatch.
[docs/keep-in-sync.md](docs/keep-in-sync.md) covers how a new release reaches the site, including a
12-line workflow that makes it happen the moment a release is published.

## Where each file comes from

| Path | Origin |
| --- | --- |
| `templates/*.html` | verbatim from keycard-shell-webapp (`choppu/update-deps`), minus the pages not ported. The tags they use are implemented by `scripts/render-pages.mjs` |
| `src/js/*.ts` | verbatim from the same branch, except the differences below |
| `src/css/style.css`, `src/img/*` | verbatim static assets (`favicon.png` comes from `static/admin/img/`) |
| `media/` | generated by `scripts/sync-upstream.mjs`; gitignored, never hand-written |
| `pages/` | generated by `scripts/render-pages.mjs`; Parcel's entry files |
| `dist/` | the site Parcel builds, published as-is |

## Differences from keycard-shell-webapp

1. **Endpoints became files.** `/update/get-db`, `/firmware/get-firmware`, `/update/get-dbs` and
   `/firmware/get-firmwares` are `media/get-db.json`, `get-firmware.json`, `get-dbs.json` and
   `get-firmwares.json`, with the same fields the Django views returned. They sit in `media/`, so
   `{% get_media_prefix %}` still prefixes both the JSON and the artifacts and the page scripts
   concatenate exactly as before.
2. **`type="module"` on the script tags.** webpack emitted IIFE scripts, Parcel emits ES modules; both
   run after the document has parsed, which is what the page scripts assume. Nothing is needed for the
   `Buffer` that webpack's `ProvidePlugin` gave `@choppu/shelljs`: Parcel's node emulation binds it in
   every module that references it, which is worth checking in the built bundle rather than assuming in
   either direction.
3. **Only the current artifacts are mirrored.** `media/firmware.bin` and `media/db.bin` are
   overwritten by each release. Upstream kept a directory per version under `MEDIA_ROOT`, but only the
   release notes need history, so `media/changelogs/<version>.md` is the one thing kept per version.
   The version history page's "Download .zip" points at the release the zip belongs to: a clicked
   download needs no same-origin copy, only the bytes that get flashed do — which is why
   `version_history.ts` no longer fetches the path it is handed.
4. **One directory of pages, built with `--public-url ./`.** URLs are `/update.html` rather than
   `/update/`: Parcel resolves relative asset and page URLs from the shared root of its entries, so
   entries in subdirectories get references that only work at the dist root. Flat pages plus a relative
   public URL mean the same `dist/` serves `keycard-tech.github.io/shell-update-site/` and a domain root
   alike, with no build flag per host. (Do not add a `targets.default` block to package.json: `default`
   is Parcel's library target, which emits root-absolute references and resolves `browser` fields
   differently.)
5. **Landing page detection.** `base.ts` recognises the landing page by path suffix instead of
   `location.pathname == '/'`, because the site can be served below a path prefix.
6. **Artifacts are checked, not trusted.** Each one must match the sha256 its release publishes
   (computed the way both repos compute it: the flashed image padded to 76 pages for firmware, minus
   the trailing signature for the database) and must carry, inside the binary, the version its release
   is tagged with — the four version bytes at offset 588 + 64 for firmware, the `0x4532` header and its
   `uint32` version for the database. A mismatch stops the build, so the previous site stays live.

## Layout

```
templates/            upstream Django templates, rendered at build time
scripts/
  render-pages.mjs    the template tags, the URL map and the static map
  sync-upstream.mjs   mirrors the releases into media/ and verifies them
src/
  css/style.css       upstream stylesheet, unmodified
  img/                upstream images, unmodified
  js/                 upstream TypeScript, unmodified apart from the differences above
pages/                generated: Parcel's entry files
media/                generated: current artifacts, changelogs, JSON
dist/                 generated: the site
docs/                 keeping in sync, the upstream release trigger
```
